# Weekly Release Notes Updater (`docs/release_notes.md`)

This skill automates gathering, categorizing, synthesizing, and documenting major weekly changes in MaxText to announce in upcoming releases.

## Workflow Steps

### 1. Gather Weekly Commits & Pull Requests

Run the helper script [gather_weekly_changes.py](../update-changelog/scripts/gather_weekly_changes.py) from the repository root to extract commits from the last 7 days (or specify `--since YYYY-MM-DD` / `--days N`):

```bash
python3 .gemini/skills/update-changelog/scripts/gather_weekly_changes.py --days 7
```

The script automatically:
- Resolves GitHub Merge PR numbers (`#XXXX`) and links them to their underlying commit titles and descriptions.
- Strips Copybara/Piper internal metadata (`PiperOrigin-RevId`).
- Checks existing PRs under `## Unreleased` in `docs/release_notes.md` to prevent duplicates.
- Categorizes changes into standard MaxText release note sections (`Changes` vs `Bug Fixes`) and domain categories.
- Filters out minor internal noise (formatting, linter fixes, reverts of typos).

### 2. Synthesize Major Release Announcements

Review the candidate list generated by the script and synthesize related commits into polished, user-facing bullet points suitable for release announcements:
- **Group related PRs**: If multiple PRs contribute to a single feature (e.g., FP8 Orbax restoration and scale tensor ingestion, or Flax NNX Linen removal), combine them into a single cohesive bullet with multiple PR links: `([PR #5051](...), [PR #5052](...))`.
- **Use MaxText Category Headings**:
  - **Model Support & Architecture** (new models, decoders, MoE routing, MTP, NNX migration)
  - **Performance** (FP8/FP4, Qwix, AQT, Muon optimizer, SparseCore, GEMM overlap)
  - **Checkpointing & Goodput** (Orbax, Zarr3, OCDBT, multi-tier checkpointing, elasticity)
  - **Post Training** (GRPO, DPO, SFT, LoRA/QLoRA, Raiden weight sync, vLLM rollout)
  - **Usability & Infrastructure** (Docker, Grain, wandb, evaluation harnesses, tutorials)
- **Exclude internal churn**: Omit minor test tweaks, linter fixes, or internal CI DAG adjustments unless they directly impact users.

### 3. Update `docs/release_notes.md`

1. Open [docs/release_notes.md](../../../docs/release_notes.md).
2. Insert the newly synthesized weekly items under `## Unreleased` (below `<!-- Add new unreleased changes below this line -->`).
3. Preserve all existing `Unreleased` and historical release entries. Do not create a root `CHANGELOG.md`.

### 4. Validation

Verify your changes before completing the task:
1. Run `git diff docs/release_notes.md` to ensure clean Markdown formatting.
2. Confirm that every PR link follows the format `[PR #XXXX](https://github.com/AI-Hypercomputer/maxtext/pull/XXXX)`.
3. Re-run `gather_weekly_changes.py --days 7` to verify that newly added PRs now appear under `Already Documented in Unreleased`.
