Worker time per merged pull request
This chart shows where each merged pull request's CI time went, worker suite by worker suite: every worker's runner wait, setup and tests, stacked. A worker suite is one test flavor of the CI workflow, for example cpu-unit, together with all of its parallel Execute Tests jobs. Bars run from the oldest merged pull request on the left to the newest on the right. Every bar is one merged pull request. Every slice is one worker suite, in its device's color. Hover a slice to follow that suite across all pull requests. Click a bar to list every suite's time in that run. Pick one suite to see one bar per worker instead. The pull request number under each bar opens that pull request on GitHub in a new tab; its merge date is under it. The chart above splits the same runs by phase.

Test suite health
This section has three parts. The table below ranks the suites whose numbers changed most, worst first; click a row to open that suite at the commit where the change began. The chart under it draws every suite’s total test time and test count per commit. Above the chart, the Suite dropdown shows one suite on its own, with its test count on the right axis, and the Every suite / Device groups toggle rolls the suites up into one line per device. The table and the chart each have their own How to read. Suite names are the test flavors of the CI workflow: tpu-unit, tpu-integration, tpu-post-training-unit, tpu-post-training-integration, gpu-unit, gpu-integration, cpu-unit, cpu-integration, cpu-post-training-unit and cpu-post-training-integration. Each one writes one test-result file per parallel worker on every run where the suite was selected, and the files of one run are added together. decoupled is the exception: it is not a job of its own but an extra pytest pass inside the cpu-unit job on worker 1, over the 4 test files marked decoupled_target, and its 50 tests are also counted inside cpu-unit. Three flavors are left out on purpose: tpu7x-unit, tpu7x-integration and tpu7x-post-training-unit run only when the workflow is not started by a pull request (scheduled, manual and release runs), so they have no pull-request data. The TPU Pathways Unit and Integration jobs write no test-result file, so they have no suite here.
